# SCUT-71 Vision Studio

智能车视觉仿真环境 —— **只写算法，其余交给环境**。

这个 VS Code 插件把「编译 → 运行 → 看画面 → 观察变量」串成一条不用读文档的路：
按 F5（或点一下「编译仿真程序」）就能看到你的边缘检测跑在 188×120 的灰度图上，
并且能在侧边栏里**自由勾选**要看哪些全局变量。

## 五分钟上手

1. 命令面板 → **SCUT-71: 环境自检**。它会实际启动各个工具取版本，
   缺什么就用中文告诉你下一步装什么。
2. 命令面板 → **SCUT-71: 新建仿真工程**，选一个空目录。
3. 改工程里 `config.h` 的 `SCUT_IMAGE_W` / `SCUT_IMAGE_H` 对齐你的摄像头，
   把你自己的测试图放进 `pic/1/`（编号从 1 开始连续；详见工程里自动生成的
   `pic/1/README-pic.txt`）。**模板不附带任何图** —— 图集是你的数据，不是环境该替你决定的东西。
4. 命令面板 → **SCUT-71: 编译仿真程序**。
5. 按 **F5** 直接调试，或打开侧边栏的 **SCUT-71 Vision → 仿真视图** 点「运行」。

全程**不需要写 `launch.json`，也不需要写任何注册代码** ——
插件的调试配置提供者会在 F5 时现场合成完整配置，变量清单由构建期自动符号发现产出。

## 侧边栏

| 区域 | 作用 |
|---|---|
| 仿真视图 | 灰度帧（`image-rendering: pixelated` 放大，边缘不会被插值糊掉）、计时读数 |
| 工具栏 | 运行 / 单步 / 运行 N 帧 / 停止 |
| 变量面板 | 自动发现的全部全局变量 + 复选框；勾上就显示数值，一维数组额外画一条小曲线 |
| 日志 | 仿真进程的 stdout/stderr 与插件自身的诊断 |

勾选状态通过 webview 的 `setState()` 持久化（而不是 `retainContextWhenHidden`，
后者内存开销大且隐藏时行为在官方文档里自相矛盾）。

## 插件自带整个 SDK（装完即用，不需要额外目录）

**装上这个 `.vsix` 就够了。** 插件内部打包了一份完整的 SDK 源码：

```
<扩展安装目录>/sdk/
├── core/include/          ← 编译你的算法时的头文件
├── core/src/              ← 核心库源码
├── bind/scut_bind.c       ← 唯一知道编译期图像尺寸的编译单元
├── backends/headless/     ← 提供 main() 的仿真宿主
└── tools/*.py             ← 官方构建脚本
```

所以你**不需要**在磁盘上另外放一份 SDK 仓库，也**不需要**把仓库当工作区打开。
插件在安装目录里找不到 SDK 时，才会退回去找仓库（那是给源码开发/F5 调试用的路径）。

> **为什么 `libscut_core.a` 是源码而不是预编译好的库？**
> 静态库里的目标文件与产生它的编译器、ABI、CRT 绑死。分发预编译的 `.a`，
> 一旦对方工具链不匹配就是一堆指不到病根的链接错误。
> 所以分发源码，在你自己的机器上用你自己的工具链编一次（约 1.5 秒），
> 之后增量复用——**改算法不再重编环境**。

> 从源码开发插件时，`extension/sdk/` 是同步生成的，不入版本库。
> 同步命令：`cd extension && npm run sync-sdk`。

## 需要的工具链

插件**不随包分发**任何第三方二进制（`clang`、`objdump`、Python 都不带），
也不会替你安装。它做的是：告诉你缺什么、为什么缺、以及装完之后要做什么。
| 工具 | 必需？ | 来源 |
|---|---|---|
| `clang` / `clang++` | ✅ 编译必需 | [LLVM-MinGW](https://github.com/mstorsjo/llvm-mingw/releases)（自带 MinGW sysroot） |
| binutils `objdump` | ⚠️ 自动变量发现必需 | MinGW-w64 / Dev-C++ 自带 |
| Python 3.7+ | ⚠️ 构建脚本必需 | python.org |
| `lldb-dap` | 可选（调试用） | LLVM-MinGW 自带 |
| `clangd` | 可选（补全用） | LLVM-MinGW 自带 |

> **为什么 `objdump` 必须是 binutils 的，不能用 `llvm-objdump`：**
> LLVM 21 移除了 `llvm-objdump --dwarf=info`（现在只支持 `--dwarf=frames`），
> 而自动变量发现正是靠这条命令读 DWARF。用 LLVM 版本会**静默失败**——
> 退出码非 0 且没有任何提示，表现为「变量面板莫名其妙一直是空的」。
> 插件会显式探测并给出这一条中文警告。

设置 `scut71.toolchainPath` 可以显式指定工具链根目录；
留空时依次探测 `SCUT71_TOOLCHAIN` 环境变量 → `D:\TOOLS\llvm-mingw` → `PATH`。

## 关于 `C_Cpp.intelliSenseEngine`

插件通过 `configurationDefaults` 把 cpptools 的 IntelliSense 默认关掉，
避免它和 clangd 互相打架。**这只是默认值**，你自己的设置优先级更高，
不会被强制覆盖。
