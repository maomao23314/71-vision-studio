## 一、设计理念（最初的需求，一切决策的出发点）

> "上手即用，代码松耦合，适应用户各种奇葩需求，模拟单片机环境（不一定是CH32）"
> "用户只需要编写自己的视觉代码，其余全部由环境解决"

**锁定的决策**：
- 环境编译成 `.a`，用户代码编译成 `.o`（库方向反转，无需 `--whole-archive`）
- 整个环境是一个 **VS Code 扩展**（不是独立程序、不是 Dev-C++）
- 工具链装到 `D:\TOOLS\llvm-mingw`，不改系统其它文件
- `SCUT_Watch` 手动注册 + DWARF 自动发现并存，自动发现为默认
- 扩展配置文件名 **"71-Vision"**

**图片显示三条要求**：
> "1、除非手动点击+-，否则自动适应。2、是否可以方便地增加功能可以拖动图片（比如我想细看某一个部分）甚至支持滚轮操作。3、就算手动点击+-后，重新拖动边框（加宽/变窄）之后也自动适应"

### 贯穿性要求（每轮都在提）

1. **"到手就能用"** — 绿勾测试 ≠ 可用；测试必须覆盖真实启动方式（第 2 轮 cwd bug、第 3 轮 picDir bug 都是因为我从工程根跑测试而插件不是）
2. **cycles 而非 µs** — 提了三遍；µs 是墙钟时间没有横向可比性
3. **别在图上画文字** — 读数走日志/变量面板，图上只留空间位置标注
4. **按钮要少而准** — 每个按钮一个明确作用，不做"三个按钮一个作用"
5. **诚实** — 没验证的说没验证；做不到的说做不到（浮动窗口=平台限制；结构体字段名=DWARF 缺口）

### 运行时数据流

```
用户代码 (camera.c)                     环境核心 (libscut_core.a)
─────────────────                       ─────────────────────────
SCUT_REGISTER(INIT,    90, ...)   →    注册表（按 role+priority 稳定排序）
SCUT_REGISTER(PROCESS,100, ...)   →
SCUT_REGISTER(DRAW,   100, ...)   →
SCUT_Watch("cam_err", ...)        →    运行期变量注册表（自动 + 手动）

每帧调度：PRE → PROCESS(计时) → POST → DRAW → 合成覆盖 → REPORT → 发布计时 → 帧接收
                                            ↑
                         DRAW 只做空间标注（边线/中线/预瞄点）
                         读数走 REPORT 的 SCUT_Log（不计时）

呈现：SCUT_OutImageSet 写输出缓冲 → 宿主 PPM/JSON → 扩展 → webview canvas
      （用户算法必须把结果写进输出图像，否则画面不更新 —— camera.c 已接线）
```

### 变量面板数据流（本轮重写的部分）

```
编译期：DWARF 自动发现 → *.vars.json → mergeManifests → manifest (44)
                                              ↓
构建后：exe --list-vars → 运行期注册表 (51，含手动 7 个) → 合并 → 完整清单
                                              ↓
扩展宿主 --select <名字列表> → 后端只统计这些 → 每帧 JSON "vars" 行
                                              ↓
webview renderVariables()：勾选区（catalog 可选全集）+ 查看区（快照实际值）
一条消息一次渲染，无时序竞态
```

### 按钮语义（本轮重整后）

| 按钮 | 键 | 作用 | 是否换图 | 是否重启进程 |
|---|---|---|---|---|
| 编译 | Ctrl+Shift+B | 构建仿真程序（含变量清单） | — | — |
| ◀ | ← | **上一张图** | 是（协议 'p'） | **否** |

| ▶\| | → | **下一张图** | 是（协议 'n'） | **否** |
| 测速 | F9 | 同一张图重复 N 次取平均 **cycles**（协议 b\<N\>，只跑计时段，后处理不参与） | 否 | **否** |
| ■ | Shift+F5 | 停止 | — | — |
| 独立窗口 | Ctrl+Alt+P | 编辑器区大图 | — | — |

**没有「运行」按钮** —— 用户原话："都说了删除运行按钮了、那玩意完全没用"。
图集推进走**运行期协议**（stdin：空行=重跑当前图，n/p=换图，g\<N\>=跳转），
进程启动后停在当前图上，翻页**不重启**、算法状态（环形缓冲/状态机/丢线计数）**保留**。

### 计时显示口径

- **主显示：周期数**（`fmtCycles`：`14.96 M` / `339.1 K` / `1234`）—— 跨机器可比
- 次显示：本机 µs（参考值）
- 折叠摘要：`14.96 M cycles`
- 测速结果：`平均 14,957,296 周期/次`

## 四、已知边界（不隐瞒）

1. **浮动窗口做不到**：VS Code 没有把 Webview 放进独立原生窗口的 API；面板模式是"既大又还在 IDE 里"的最优解
2. **结构体字段展开是近似的**：按 4 字节字长摊开，字段名不可知（需 DWARF 成员表，是明确的后续工作）
3. **PNG 支持的子集**：8 位灰度/真彩/调色板、非交织；16 位/RGBA/Adam7/JPEG 明确报错
4. **中文文字不支持**：内置 8×8 ASCII 字库
5. **没有在真实 VS Code 窗口手动点过**：渲染/协议/构建各自独立验证过，人机链路需要用户确认
6. **仿真 ≠ 真机性能**：默认 -O0，看优化后耗时用 release 模式
