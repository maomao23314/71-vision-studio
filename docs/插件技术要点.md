## 一、三个必须知道的坑（会直接导致代码写错）

### 坑 1：`registerWebviewViewProvider` 的选项**不是** `WebviewOptions`

`vscode.d.ts:11749` 的第三个参数是内联匿名类型，**只接受 `retainContextWhenHidden`**：

```ts
window.registerWebviewViewProvider(
  viewId: string,
  provider: WebviewViewProvider,
  options?: { readonly webviewOptions?: { readonly retainContextWhenHidden?: boolean } }
): Disposable
```

`enableScripts` / `localResourceRoots` **不能**写在这里（类型错误），必须写进
`resolveWebviewView` 里的 `view.webview.options`（`Webview.options` 是可写的，`9954`）：

```ts
resolveWebviewView(view: vscode.WebviewView, _ctx, _token): void {
  view.webview.options = {                       // ← 在这里设
    enableScripts: true,
    localResourceRoots: [vscode.Uri.joinPath(this.ctx.extensionUri, 'media')]
  };
  view.webview.html = this.html(view.webview);
}
```

### 坑 2：帧数据**不要用 base64**

`Webview.postMessage`（`10023`）**没有** `transfer` 参数。但当 `engines.vscode >= 1.57` 时，
`ArrayBuffer` 会走**结构化传输的快路径**。

这一点在**发行版源码**里核实过（`extensionHostProcess.js` 的 `function Za(i){...minorBase>=57}`），
并由维护者给出实测数字（[microsoft/vscode#115807](https://github.com/microsoft/vscode/issues/115807#issuecomment-851013383)）：

> webview → 扩展宿主 约 4 s → **400 ms**；扩展宿主 → webview 约 10 s → **500 ms**（约 10–20 倍）

**所以：直接 post `Uint8Array`/`ArrayBuffer`，在 webview 侧扩成 RGBA 再 `putImageData`。**
不要 base64、不要临时 PNG。

> ★ 连带陷阱：`workspace.fs.readFile` 返回的是 Node `Buffer`，**不走**快路径，
> 必须包一层 `new Uint8Array(...)`。

### 坑 3：`--install-extension --profile NAME` **不会**自动建 profile

`code --help` 说 profile 会自动创建，但那只适用于**打开**路径。
安装路径下若 profile 不存在会**直接失败**（实测退出码 1，报 `Profile 'xxx' not found.`）。

**顺序必须**：先 `code --profile "NAME" <folder>` 建好，再装扩展。

### 无 `launch.json` 起 F5 的机制

`resolveDebugConfiguration`（`16822`）的契约（`16814-16815`）：

- 返回**配置** → 会话启动
- 返回 `undefined` → 会话**不启动**
- 返回 `null` → 不启动，**并打开底层的 launch.json**

因此用户按 F5 且无 `launch.json` 时，VS Code 会传一个只有 `type`/`request`/`name` 的空壳配置进来，
我们**补齐并返回**即可，全程不落盘任何 JSON。

### 激活事件（1.90+ 仍需显式声明）

`commands`/`views`/`languages`/`customEditors`/`authentication` 是**隐式**的。
但 `onDebug*` 系列**不是**，必须显式写：

```jsonc
"activationEvents": [
  "onDebugResolve:scut71",   // F5 无 launch.json 的路径
  "onStartupFinished"        // 需要启动时检测 cpptools 冲突
]
```

## 三、clangd 集成

### `vscode.d.ts` 里**没有** LSP 客户端 API

全文 grep `LanguageClient|LanguageServer|TransportKind` → **零命中**。
必须使用 npm 包 **`vscode-languageclient`**（当前 **10.1.2**）。

> ⚠️ `@vscode/languageclient` **不存在**（npm 404），不要写错包名。

外部二进制（clangd）走 **stdio**，**不要**用 `TransportKind.ipc`（那是 Node 专用）：

```ts
const serverOptions: ServerOptions = {
  run:   { command: clangdPath, args: [], options: { env: childEnv } },
  debug: { command: clangdPath, args: [], options: { env: childEnv } },
};
```

### 生成哪个配置文件

| 文件 | 语义 | 建议 |
|---|---|---|
| `compile_flags.txt` | 每行一个参数，**对所有文件相同**；路径相对该文件所在目录 | ✅ **默认用它** |
| `compile_commands.json` | 每个 TU 一条，可差异化 `-I`/`-D` | 需要 per-file 差异时才用 |

**两者不要放在同一目录**（clangd 视为互斥的同一数据库）。
放在工作区根，让 clangd 向上查找时命中。

### 与 cpptools 的冲突

clangd 官方扩展的做法（可直接照抄）：检测 `ms-vscode.cpptools` 是否激活，
若 `C_Cpp.intelliSenseEngine !== 'disabled'` 则提示用户关闭。

**更省事的做法**（不改用户配置，只提供默认值）：

```jsonc
"contributes": {
  "configurationDefaults": {
    "C_Cpp.intelliSenseEngine": "disabled"
  }
}
```

> ⚠️ 不要用 `extensionDependencies: ["ms-vscode.cpptools"]` ——
> 那会**强制安装**这个许可证受限的扩展，与项目原则冲突。

## 四、性能与生命周期

| 事项 | 结论 |
|---|---|
| 帧体积 | 188×120 灰度 = **22560 B**。base64 后 30080 B（+33%）。30 fps ≈ 0.9 MB/s，**不是瓶颈** |
| 真正的成本 | **每条消息的序列化**（跑在扩展宿主线程上），不是带宽 |
| `postMessage` 返回值 | 返回 `true` **不代表** webview 收到了（`10016-10018`）。**必须自己定义 ACK** |
| 背压 | 同一时刻只允许一帧在途；宁可丢帧也不要排队（排队 = 无界内存增长） |
| `retainContextWhenHidden` | 默认 **`false`**。帧是派生状态，重新可见时恢复推流即可 |
| 隐藏时推流 | `.d.ts` **自相矛盾**（`9995-9996` 说可以，`10071-10072` 说不可以）。**设计上不依赖它** |
| 正确做法 | 订阅 `onDidChangeVisibility`，`visible === false` 时**暂停产帧** |

## 五、打包

```bash
vsce package --allow-missing-repository --no-dependencies -o scut71-vision-studio-0.1.0.vsix
```

| 要点 | 说明 |
|---|---|
| `--allow-missing-repository` | **必需**。否则 `package.json` 缺 `repository` 会**交互式阻塞**询问 |
| `--no-dependencies` | 配合打包器使用，不扫描 `node_modules` |
| `.vscodeignore` 与 `package.json` 的 `files` | **互斥**，同时存在会直接报错退出 |
| `README.md` | 若含模板文本 `This is the README for your extension ` 会**拒绝打包** |
| `publisher` | 必填 |
