# 给 AI / 维护者的交接说明

> 读完 `docs/架构设计.md`（当前行为的唯一权威）再看这一份。
> 本文件**不是**过程性评审报告，是可长期留在仓库里的交接材料（已进 Git）。
> 这里只写**代码里看不出来、但改错会出事**的东西：设计约束、用户明确提出的要求、
> 以及那些"看起来像 bug、其实是有意为之"的地方。

---

## 一、不能动的设计约束

| 约束 | 为什么 | 改错的后果 |
|---|---|---|
| 输入图 `mt9v03x_image` 地址恒定 | 算法里常有逆透视指针表（`uint8_t *PerImg_ip[H][W]`），开机建一次长期用 | 换缓冲 → 表里指针全部悬空，读随机内存，不报错 |
| 结果图只做逐像素深拷贝 | 同上 | 换指针 → 同上 |
| 图像尺寸是编译期常量 | `int line[SCUT_IMAGE_H]` 这类声明到处是，C 要求常量 | 运行期改尺寸 → 编不过 |
| 帧内顺序：PROCESS → 默认底图 → DRAW → 合成 → 清空 → sink | 顺序错一个位置就是"标注慢一帧""标注全消失"这类静默错误 | 见 `core/src/scut_sched.c` 的 `run_one_frame` |
| 勾选变量只是宿主侧显示过滤 | 用户要求"勾选后不需要重新编译/重启" | 改成传 `--select` = 改勾选要重启进程 |
| 用户代码零注册宏 | 代码要能原样拷进车载工程 | 加 `SCUT_INIT` 之类 → 车载工程编不过 |
| 图片2（`SCUT_OutImageSet(2, …)` / `SCUT_EnvCopyOutput(2, …)`）**每帧清空** | "黑"必须只有一个含义：这帧什么都没写 | 不清 → 算法这帧没画却留着上一帧，看起来像"这帧也算出了同样结果" |
| 输出图写入**只有一处**（`core/src/scut_input.c` 的 `out_store`，第一个参数 1 / 2 选图） | 两块图语义完全一样，两份实现迟早漂移 | 单开一套 `*2` 函数 → 每个调用点都要重新判断用哪个，选错还不报错 |

## 二、用户明确提过的要求（原话见 `docs/改动流水账.md`）

- 用户代码**恒 `-g -O0`**，环境自身恒 `-O2`。**没有"编译模式"开关**，不要加回来。
- 翻页、重跑、测速**都不重启进程**：算法内部状态（环形缓冲、状态机、丢线计数）要保留。
  ★ 连续播放（「运行 N 帧」）已经整个删掉了，别再以"保留状态"为由把它加回来 ——
    用户明确说它没意义。
- 绘制与日志**不计入** `process_us`。
- 计时以**周期数**为主，微秒只作参考。
- 配置只有一个真值：工程根的 `scut_project.json`。**不要**再把配置拆回 VS Code `settings.json`。
- 工具链是"问用户"，**不要**猜安装目录（猜目录被证伪过两次）。
- 变量发现**不要**再引入外部程序依赖（objdump/objcopy 那一套已经删掉了，
  它是"纯净机器上变量面板必然为空"的根因）。
- 两块画面（图片1 / 图片2）**各自独立的折叠与缩放**，不要合并成一份状态。
  两栏**默认都收起**，标题就写「图片1」「图片2」。
- 两栏**恒在**，没有"要不要显示图片2"的开关。用户原话：「不要选择开启」。
  曾经加过一版 `display.secondImage`，已经删了；`scut_project.json` 里也**不要**
  再加回这类"显示开关"——想收起就点头题，不需要工程配置参与。
- **不要加回「运行（连续跑 N 帧）」**。它与「测速」重复又给不出结论，用户要求删掉；
  连带的 `runFrames` / `run.runFrames` / `scut71.run` / `F8` 都删了，播放图标归「编译」。
- 选图**直接用数字 1 / 2**，不要加 `SCUT_IMG_1` 之类的宏。用户原话：
  「SCUT_IMG_1 这种宏定义不是越来越麻烦？应该精简用户的使用条件，直接 12 不行吗」。
- **视图内的快捷键一律写在 `media/simview.js` 的 keydown 里，不要绑进 `keybindings`**。
  `+`/`-`/`←`/`→`/`F9`/`Shift+F5` 曾经绑在 keybindings 上
  （`when: view == scut71.simview`），**从来没生效过**；现在全在页面里处理。
  绑回去不是"多一层保险"，是双触发：页面发一次、VS Code 再发一次。
  `tests/test_cleanup.py` 守着"keybindings 里不许再出现它们"。
- **不要再给插件加第二个页面**（比如"独立监控窗口"）。0.10.7 做过一版
  `WebviewPanel`，撤了：VS Code 插件开不出真正的独立窗口，
  而两个页面看同一份数据，只会让"去哪看"变成一道选择题。
  真要看大图，把侧边栏拖宽。
- **配置面板里每个字段都必须有分组接收**。`configfields.ts` 的 `SectionDef`
  有 `key`（DOM id）和 `keys`（负责哪些一级配置键）**两个**字段，别合并。
  合并过一次，后果是 `outputArray`（结果图数组名）从 0.9.4 到 0.10.8
  **从来没有显示过** —— 因为一个分组只能装一个一级键。
  `tests/test_firstrun.py` §1 用【集合覆盖】守着（不是"分组名等于字段前缀"，
  那个判据恰好让缺陷通过）。
- **钩子候选扫描只做建议、不做决定**（`hookscan.ts`）。
  扫不出来时必须返回空表、让用户手填 —— 静默填一个错的函数名，
  用户会以为环境坏了。别为了"看起来更智能"去猜。
- **「配置本工程」向导已删除，不要再加回来**。它和配置面板写同一个 JSON，
  只问两项、其余仍要去面板改，用户得在两套界面之间来回。
  新建工程时该问的已经问完了（尺寸 + 处理函数）。
- **不要再写一份 `isFile` / `isDir`**。四份重复的实现已收敛到 `fsutil.ts`。
  它们的语义是"任何异常都回答 false"，改这个语义会同时影响
  工程识别、工具链探测、构建脚本定位三条链路。
- **配置面板的自动保存是"延迟合并 + 宿主落盘"，别改成前端防抖**。
  延迟计时器必须活在扩展宿主里：webview 的计时器随页面销毁而消失，
  改完立刻关面板就会丢那次改动。落盘在 `settingsview.ts` 的
  `flushPending()`，`onDidDispose` / `reload` / 关开关三处都要调它。
  `tests/test_autosave.py` 用真实磁盘断言守着（10 条，含"关掉开关后不许再写"）。
- **自动保存开关不许进 `scut_project.json`**。它是本机习惯，存
  `context.globalState`。工程 JSON 只放"这个工程怎么跑"的事实。
- **宿主侧必须自己判一次 `readAutoSave()`**，不能只信前端发来的 `autoSave`
  消息。实测过：关开关的同一瞬间改一项，前端状态差一拍，消息照样发出来。

## 三、看起来像缺陷、其实不用修

1. **结果图尺寸与配置不一致时，只显示左上角并填黑，不告警。**
   这是设计选择：图像尺寸是编译期契约，运行期不会随便改。用户改尺寸必然伴随重编译，
   而重编译时算法里的数组也一起变了。`core/src/scut_input.c` 的 `SCUT_EnvCopyOutput`
   按"两边都有的部分"裁剪，避免越界写。

2. **`SCUT_GetInputImage` 在非 PROCESS 阶段返回 NULL 并往 stderr 打一次警告。**
   这是"防止把图像处理藏进不计时区域"的机制。绝大多数用户直接读全局数组，
   所以这条门控实际上很少触发——这是有意的诚实边界，不是实现漏了。

3. **用户代码里不要写 `main()`。**
   `main` 由呈现后端提供（`backends/headless/`）。用户写一个会撞车。
   构建脚本会在用户 `.c` 里检测 `main` 的定义并提前给出中文提示，
   所以正常情况用户不会走到链接期才看到 `duplicate symbol: main`。

4. **同一个函数不能填进两个阶段。**构建脚本会拦下来并解释原因
   （它会每帧跑两遍，而只有一遍计入计时）。

5. **`SCUT_DrawText` 只支持 ASCII。**内置 8×8 字库，非 ASCII 画占位方框。
   要显示数值用 `SCUT_Log` 或变量面板。

6. **从未被引用的 `static` 变量发现不了。**被编译器删掉了，与调试器行为一致。

7. **结构体只显示整体大小，不显示字段。**环境不解析 DWARF 成员表。
   要看字段就 `SCUT_Watch` 单独注册该成员。

8. **图片2 某一帧没画就是一张黑图，那一栏不会消失。**
   "图片2 被用过"是按【进程】记的账：一旦写过，后端之后每帧都会发这张图。
   所以算法里 `if (第一帧) 往图片2画` 之后，后面每一帧都是黑的 —— 这是对的，
   黑的含义就是"这一帧什么都没写"。`tests/second_session.js` 的 `without` 场景守着它。

9. **`+`/`-` 在焦点回到编辑器后就不灵了。**
   这是浏览器的焦点模型，不是 bug：没有焦点的页面收不到 keydown。
   而这正合我们的意 —— 你在 `.c` 里敲 `+` 永远是加号。
   要"在任何地方都灵"只能绑全局快捷键，那会跟写代码抢键，用户明确担心这件事。

## 四、改代码前值得先看的几处"坑"

| 位置 | 坑 |
|---|---|
| `tools/scut_symbols.py` 生成的包装单元 | `#include` 用户源码后直接跟构造函数。用户源码末尾若有未闭合注释/`#if`，会把注册代码吞掉 |
| `tools/scut_dwarf.py` | 纯标准库的 DWARF 读取器。**别按印象写 DWARF 字段编号/宽度**——编译单元头、属性编号、form 宽度三处都错过一次，表现全是"变量名跑到隔壁去了"且不报错。改完必须跑 `tests/test_dwarf.py` |
| `tools/scut_build.py` 的 `write_glue` | 钩子函数名只校验是不是合法 C 标识符，**没有**校验它是否真的存在——后者靠链接期报错 |
| `tools/scut_build.py` 的 `_core_fingerprint` | 核心库增量重建的判据。改了 `core/`、`bind/` 或编译器身份都会变；改了别的地方不会 |
| `extension/scripts/sync-sdk.js` | 改了 `core/ bind/ backends/ tools/ templates/` **必须**跑一次 `npm run sync-sdk`，否则打出的 vsix 带旧代码 |
| `tests/test_cleanup.py` | 很多断言用"文件里出现过某个词"当判据，容易假绿。新增断言请尽量精确到行/函数 |
| `tests/test_firstrun.py` | 守的是"第一次用的人会不会卡住"。这类缺陷【不影响任何已有行为】，跑其它测试全绿也可能卡在第一步。改配置面板 / 引导页 / 新建流程后必须跑它 |
| `tests/test_autosave.py` | 守的是自动保存的**行为**（真的跑 settingsview、对真实磁盘断言）。失效方式全是静默的：中间态被逐次写盘、关面板丢改动、reload 刷回旧值、关开关还在写。改这块必须跑 |
| `extension/src/settingsview.ts` 的 `flushPending()` | 三处必须调它：`onDidDispose`（关面板）、`reload`（切回来）、`setAutoSave`（关开关）。漏任何一处都是静默丢改动 |
| `extension/src/hookscan.ts` | 钩子候选扫描是**正则**，不是 C 解析器。判据只有三条：返回 `void`、形参 `void`、前面没有 `static`。放宽任何一条都会把不能当钩子的函数列进去 |
| `extension/media/settingsview.js` 的 `render()` | 按分组的 `sec.keys` 过滤字段，**不要**改回 `f.path[0] === sec.key`（那会让一个分组只能装一个一级键，见 `outputArray` 那次） |
| `extension/src/simargs.ts` | 侧边栏会话与「调试」两条入口共用它拼图集参数，改这里两边一起变 |
| `extension/media/simview.js` 的 `createPane` | 两块画面是同一个组件的两个实例。**别把其中一块单独复制一份**改——那一定会漂移（本文件里已经有过"四个折叠区块各写一份"的同源教训） |
| 图片2 的"有没有被用过" | 记在 `bind` 单元（它拥有那块缓冲）。后端据此决定要不要多写一张 PPM；**不要**改成"永远写"，那会让不用这个功能的工程白白多一次文件读写 |
| 改动 `scut_sdk.h` 里的用户接口 | 插件还没发布，"不考虑兼容旧工程"是用户拍板的。但改了签名之后，用户手头那些工程（不在本仓库里）会编不过。改完要在提交信息或交接里点明"需要跟着改哪几个调用"，别让人自己猜 |
| 文档里**不要写死任何具体工程路径** | 测试工程在仓库外、名字归用户。写成某个人的目录名，别人 clone 下来就对不上，也等于把开发机的目录结构带进仓库。`tests/test_cleanup.py` 第 20 节会扫 `*.md` |

## 五、已知边界与取舍（有意为之）

- **变量发现已经不依赖 objdump 了**。`tools/scut_dwarf.py` 直接读 `.debug_info`
  的字节（PE/COFF + ELF、DWARF 4 + 5、zlib 压缩、ELF 重定位）。
  只要编译能过，变量面板就有内容。**不要再把 binutils 加回必需清单**——
  当初那套要求是"纯净机器上变量面板必然为空"的根因。
- **Python 3.7+**：构建脚本用，零第三方库依赖。**插件不代下载**，要求用户自装
  （python.org / Anaconda 都行），在配置面板「工具链 › Python 解释器路径」里指过去。
- **clangd**：可选、只做「发现 + 建议」。插件不会启动语言服务，也不会因此降级任何功能；
  自检报告里那句提示只是"装了会更准"。不要给它加隐含依赖。
- **`--backend` 只有一个合法取值**：这一层是给未来后端预留的接口，不是漏填。
- **`scut_sched_set_log_enabled` / `set_draw_enabled`**：后端已接 `--no-log` / `--no-draw`，
  命令行与 CI 可用；插件面板还没有对应开关。
- **`ToolInfo` 接口没有消费者**：`toolInfos()` 已删（零调用、与 `runDoctor` 重叠），
  但这个接口留着 —— 它是**数据形状**不是**开关**，将来做工具面板直接用得上。
  与"死界面"（用户能看见却没人读）不是一类东西。
- **引导页只在"跑不起来"时出现**：判据是 `ProjectInfo.hooksReady`，
  与构建脚本的校验口径一致（`init_names or frame_names`）。
  仿真正在跑时一律不挡画面。
- **后端的 `--advance`（每帧自动换图）保留**：那是命令行/CI 的能力。
  插件侧删掉的只是"连续播放"那一层，不要因为删了按钮就把 `--advance` 也删了。
- **会话接口里的 `step()` 目前没有按钮调用**（连续播放删了之后，"重跑当前图"
  这条协议命令就没有入口了）。保留它是因为它对应后端一个明确的协议命令，
  而且是 `tests/run_frames.js` 验背压用的 —— 属于接口，不是死代码。
  要给用户入口的话，接一个「重跑这一帧」按钮即可。

## 六、下一步优先级（如果接手继续做）

1. 协议字段名只在一边定义的工具化（C 侧与 TS 侧共享一份字段表）。
2. 手写注册的判据目前靠"清单里没有、注册表里有"这条运行期事实；
   `core` 里保留的 autoTag 只是辅助信息，别让宿主逻辑隐式依赖它。
