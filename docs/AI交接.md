# 给 AI / 维护者的交接说明

> 读完 `docs/架构设计.md`（当前行为的唯一权威）再看这一份。
> 本文件**不是**过程性评审报告，是可长期留在仓库里的交接材料（已进 Git）。
> 这里只写**代码里看不出来、但改错会出事**的东西：设计约束、用户明确提出的要求、
> 以及那些"看起来像 bug、其实是有意为之"的地方。

---

## 一、不能动的设计约束

| 约束 | 为什么 | 改错的后果 |
|---|---|---|
| 输入图 `mt9v03x_image` 地址恒定 | 算法里常有逆透视指针表（`uint8_t *PerImg_ip[H][W]`），开机建一次长期用 | 换缓冲 → 表里指针全部悬空，读随机内存，不报错 |
| 结果图只做逐像素深拷贝 | 同上 | 换指针 → 同上 |
| 图像尺寸是编译期常量 | `int line[SCUT_IMAGE_H]` 这类声明到处是，C 要求常量 | 运行期改尺寸 → 编不过 |
| 帧内顺序：PROCESS → 默认底图 → DRAW → 合成 → 清空 → sink | 顺序错一个位置就是"标注慢一帧""标注全消失"这类静默错误 | 见 `core/src/scut_sched.c` 的 `run_one_frame` |
| 勾选变量只是宿主侧显示过滤 | 用户要求"勾选后不需要重新编译/重启" | 改成传 `--select` = 改勾选要重启进程 |
| 用户代码零注册宏 | 代码要能原样拷进车载工程 | 加 `SCUT_INIT` 之类 → 车载工程编不过 |

## 二、用户明确提过的要求（原话见 `docs/改动流水账.md`）

- 用户代码**恒 `-g -O0`**，环境自身恒 `-O2`。**没有"编译模式"开关**，不要加回来。
- 翻页、连跑、测速**都不重启进程**：算法内部状态（环形缓冲、状态机、丢线计数）要保留。
- 绘制与日志**不计入** `process_us`。
- 计时以**周期数**为主，微秒只作参考。
- 配置只有一个真值：工程根的 `scut_project.json`。**不要**再把配置拆回 VS Code `settings.json`。
- 工具链是"问用户"，**不要**猜安装目录（猜目录被证伪过两次）。

## 三、看起来像缺陷、其实不用修

1. **结果图尺寸与配置不一致时，只显示左上角并填黑，不告警。**
   这是设计选择：图像尺寸是编译期契约，运行期不会随便改。用户改尺寸必然伴随重编译，
   而重编译时算法里的数组也一起变了。`core/src/scut_input.c` 的 `SCUT_EnvCopyOutput`
   按"两边都有的部分"裁剪，避免越界写。

2. **`SCUT_GetInputImage` 在非 PROCESS 阶段返回 NULL 并往 stderr 打一次警告。**
   这是"防止把图像处理藏进不计时区域"的机制。绝大多数用户直接读全局数组，
   所以这条门控实际上很少触发——这是有意的诚实边界，不是实现漏了。

3. **用户代码里不要写 `main()`。**
   `main` 由呈现后端提供（`backends/headless/`）。用户写一个会撞车。
   构建脚本会在用户 `.c` 里检测 `main` 的定义并提前给出中文提示，
   所以正常情况用户不会走到链接期才看到 `duplicate symbol: main`。

4. **同一个函数不能填进两个阶段。**构建脚本会拦下来并解释原因
   （它会每帧跑两遍，而只有一遍计入计时）。

5. **`SCUT_DrawText` 只支持 ASCII。**内置 8×8 字库，非 ASCII 画占位方框。
   要显示数值用 `SCUT_Log` 或变量面板。

6. **从未被引用的 `static` 变量发现不了。**被编译器删掉了，与调试器行为一致。

7. **结构体只显示整体大小，不显示字段。**环境不解析 DWARF 成员表。
   要看字段就 `SCUT_Watch` 单独注册该成员。

## 四、改代码前值得先看的几处"坑"

| 位置 | 坑 |
|---|---|
| `tools/scut_symbols.py` 生成的包装单元 | `#include` 用户源码后直接跟构造函数。用户源码末尾若有未闭合注释/`#if`，会把注册代码吞掉 |
| `tools/scut_build.py` 的 `write_glue` | 钩子函数名只校验是不是合法 C 标识符，**没有**校验它是否真的存在——后者靠链接期报错 |
| `tools/scut_build.py` 的 `_core_fingerprint` | 核心库增量重建的判据。改了 `core/`、`bind/` 或编译器身份都会变；改了别的地方不会 |
| `extension/scripts/sync-sdk.js` | 改了 `core/ bind/ backends/ tools/ templates/` **必须**跑一次 `npm run sync-sdk`，否则打出的 vsix 带旧代码 |
| `tests/test_cleanup.py` | 很多断言用"文件里出现过某个词"当判据，容易假绿。新增断言请尽量精确到行/函数 |
| `extension/src/simargs.ts` | "运行"和"调试"两条入口共用它拼图集参数，改这里两边一起变 |

## 五、已知边界与取舍（有意为之）

- **objdump**：自动符号发现依赖 binutils 的 `objdump --dwarf=info`。
  LLVM 21 已移除该选项，llvm-mingw 自带的 `objdump` 只是转发脚本，用不了。
  **插件自己下载的工具链不含可用的 objdump**；缺它时变量面板为空，编译和运行不受影响。
  这是当前"到手即用"的已知缺口，见 `docs/AI交接.md` 第六节。
- **Python 3.7+**：构建脚本用，零第三方库依赖。**插件不代下载**，要求用户自装
  （python.org / Anaconda 都行），在配置面板「工具链 › Python 解释器路径」里指过去。
- **clangd**：可选、只做「发现 + 建议」。插件不会启动语言服务，也不会因此降级任何功能；
  自检报告里那句提示只是"装了会更准"。不要给它加隐含依赖。
- **`--backend` 只有一个合法取值**：这一层是给未来后端预留的接口，不是漏填。
- **`scut_sched_set_log_enabled` / `set_draw_enabled`**：后端已接 `--no-log` / `--no-draw`，
  命令行与 CI 可用；插件面板还没有对应开关。

## 六、下一步优先级（如果接手继续做）

1. 自动符号发现换掉 objdump：解析 `.debug_info` 原始字节（格式稳定，不依赖工具链版本）。
2. 协议字段名只在一边定义的工具化（C 侧与 TS 侧共享一份字段表）。
3. 手写注册的判据目前靠"清单里没有、注册表里有"这条运行期事实；
   `core` 里保留的 autoTag 只是辅助信息，别让宿主逻辑隐式依赖它。
