## 第二轮反馈（七条 + 一条补充）

### 7.1 界面是一堆堆叠的栏目 / "变量面板"漏出来

**根因（两层）**：

1. **注册了两个侧边栏视图**（`仿真视图` + `变量面板`），共用一份脚本、
   靠 `data-kind` 隐藏其中一半 —— 这就是你截图里那个"漏出来的变量面板"。
2. 单视图内部又是五个 `section` 平铺。

**修法**：
- **只留一个视图**（`仿真`），删掉 `变量面板` 视图及其全部注册/菜单/引用。
- 五个区块改成**统一的可折叠组件**：

  | 区块 | 默认 | 折叠标题显示 |
  |---|---|---|
  | 选择要观察的变量 | 折叠 | 已勾 N / 总数 |
  | **变量查看** | **展开** | 已看 N / 总数 |
  | 计时 | 折叠 | 处理时间 |
  | 日志 | 折叠 | 行数 |

  > 你点出的"计时菜单为什么要做的跟变量面板不是同一种组件"——
  > 根因就是它们各写了一份折叠逻辑。现在四个区块共用
  > `setOpen/toggle/bindCollapsible`，行为与持久化天然一致。

### 7.2 处理完的赛道输出没显示（**最重要的 bug**）

**根因**：扩展启动仿真时 `cwd` 设成 **exe 所在目录**（`<工程>/.scut/bin/`），
而图集路径 `pic/1` 是相对**工程根**的 → 找不到任何图 → 静默跑黑图。

```
从 <工程>\ 启动      → "pic":"pic/1/1.bmp"  ✅
从 .scut\bin\ 启动   → 找不到图 → 全黑        ← 插件用的正是这种
```

**修法**：仿真程序**按 exe 自身位置反推工程根**，
依次尝试 `<exe目录>/..`、`<exe目录>/../..`、CWD，
第一个真的有 `1.bmp` 的胜出。实测三场景全部命中：

```
无关 CWD + 相对默认  : pic\1\1.bmp
无关 CWD + 绝对 --pic : pic\1\1.bmp      ← 修前返回 "pic":"C:"
工程根 CWD           : pic\1\1.bmp
```

> 顺带修掉子代理留下的 bug：绝对 `--pic` 被当成"候选根"放进 roots[]，
> 又拼了一次 `dir`，得到 `<绝对目录>/pic/1`，下游把字符串剥到只剩盘符。

### 7.3 大日志常驻

日志**默认折叠**，标题显示行数 —— 折起来看不见内容，
但"有没有新日志"一眼可见。

### 7.4 变量勾选与查看混在一起 → 拆成两块

| 区块 | 职责 | 默认 | 交互 |
|---|---|---|---|
| **选择要观察的变量** | 决定"观察哪些"（配置） | 折叠 | 复选框 + 名字过滤 + 全选/全不选/**只选关键** |
| **变量查看** | 看当前帧的值（数据） | **展开** | 只显示勾中的；一维数组画曲线 |

"只选关键"用名字启发式（阈值/边线/中线/偏差/状态），
不依赖硬编码符号名；匹配不到就退回全选，保证永远有正面效果。

### 7.5 结构体看不到细节

结构体/指针条目加了"**展开字段**"按钮。
但必须诚实：C 运行期**没有类型信息**，核心只知道"这块内存多大"（如 `<104B>`），
拿不到字段名与偏移（那需要解析 DWARF 的 `DW_TAG_member`）。
所以现在的展开是**按 4 字节字长的近似解读**，并**明确标注"字段名不可知"**——
而不是伪造一排精确数字。精确命名是明确的后续工作。

### 7.6 连续运行永远是同一帧

两个独立问题：
1. 图集没加载（见 7.2）。
2. `--advance` 语义 = 连续运行时每帧**换下一张图**（到末尾回卷）。
   实测连续 5 帧：`1.bmp → 2.bmp → 3.bmp → 4.bmp → 5.bmp`，无重复。
   做纯性能计时（同一张图反复跑）时在设置里关掉 `advancePerFrame`。

### 7.7 还留 config.h 干嘛

| 配置 | 放哪 | 为什么 |
|---|---|---|
| 图集目录/后缀/起始张号/每帧推进/重复次数 | **VS Code 设置**（新增 5 个 `scut71.*`） | 运行期行为，改完立即生效 |
| **图像宽高 `SCUT_IMAGE_W/H`** | **必须留在 config.h** | C 里数组大小是编译期常量，用户算法里到处是 `int left_line[SCUT_IMAGE_H]`；运行期改不了 |

`config.h` 保留宏作为**脱离 IDE 也能跑**的默认值（命令行批处理场景）。

### 7.8 图片显示三点要求

| 要求 | 实现 |
|---|---|
| **默认自动适应** | 不在手动缩放模式时，画面宽度始终填满可用宽度 |
| **可拖动 + 滚轮** | 左键拖动平移；滚轮缩放且**以光标为锚点** |
| **拖边框后重新适应** | `ResizeObserver` 监听**容器**（不是 `window.resize`——拖侧边栏边框时窗口尺寸不变，只有容器变） |

**手动/自动切换**：默认自动适应；点 `+`/`−`/滚轮 → 进入手动模式，
拖边框不再改缩放；点「适应」或 `Ctrl+0` 回自动模式。

## 移植真实视觉算法

`集成仿真环境测试\scut71-project\code\` 六个文件 2890 行。

**保真度是机械核验的**：与原始 1790 行算法主体逐行比对，
**只有 4 行不同，新增 17 行全是注释**。每个算法语句逐字一致
（大津法、sobel、差比和判边、找起始点、逐行搜边、横向搜线、环岛识别、预瞄点、逆透视）。

适配项：`__no_init`/`#pragma location` 移除（Cyt4BB7 固定地址，PC 无意义）、
厂商头文件换 `scut_sdk.h`、`MT9V03X_*` 映射 `SCUT_IMAGE_*`、
调参值按原值保留（`ratio_thres=160` 等）、裸 `inline`→`static inline`（修链接）、
逆透视指针表给独立副本（防悬空）。

**运行证据**：`OTSU 112 / MEAN 63`（全黑图会是 1）、`ERR -2`、`TP 2`、
`exact_len 56.8/72.9` 与 `track_far 55/70` 吻合、`PerImg_ip` 非 NULL 真实地址。
截图 `docs/proof_real_algorithm.png` 可见 `LANE LONG_STRAI / CIR CIRCLE_NON / ERR -2`。

**修正一处移植副作用**：移植者把大津法探针放在 **PROCESS 内部**（被计时），
O(256²) 扫描把读数从算法自身的 ~45–90 µs 抬到 **540–770 µs**。
已移到 REPORT（不计时），修正后 **41–55 µs**。

## 我犯过的错（记录）

1. **忘了 bump 版本号**：文件名叫 0.4.0 里面却是 0.3.0，
   `code --install-extension` 报成功但装的还是旧版 —— 两轮才定位到。
2. **`Set-Content` 写 `package.json` 带了 BOM**，`vsce` 直接拒绝
   （`Unexpected token '﻿'`）。
3. **测试没覆盖真实启动方式**：上一轮"测试全绿但用不了"已暴露盲区，
   这轮 CWD 这个根因依然靠你实测才发现 ——
   因为我所有测试都从工程根跑，而插件不是。
   **教训：测试必须覆盖真实的启动方式，而不是最方便的启动方式。**
4. 上一轮"测试全绿但完全不能用"的根本原因是：
   我把"测试通过"当成了"能用"。两者之间隔着**真实的用户操作路径**。
