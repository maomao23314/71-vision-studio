================================================================================
 pic/ —— 这里放【你自己的】测试图集
================================================================================

为什么是空的？
    这组图不是环境该替你决定的东西。不同的摄像头、不同的赛道、不同的光照，
    需要的图完全不同。与其塞给你一组"别人的图"让你误以为那才是标准，
    不如把文件夹留空，让你放自己的实拍图。

--------------------------------------------------------------------------------
 一、目录怎么放
--------------------------------------------------------------------------------
    工程根目录/
    └── pic/                    ← 图直接放这里（默认就读这个目录）
        ├── 1.bmp               ← 文件必须从 1 开始【连续】编号
        ├── 2.bmp
        ├── 3.bmp
        └── ...

    ★ 编号必须连续，中间不能跳号。
      环境从第一张开始一张张往后读，读到缺号就认为这组图结束了。
      例如只有 1.bmp、2.bmp、4.bmp，那么 4.bmp 永远不会被读到。
      从 1 起编号是旧约定；若目录里有 0.bmp（或 0.png），环境会自动改成 0 起编号。

    ★ 每张图都必须大小一致（都等于 scut_project.json 里 image.width ×
      image.height）。尺寸不一致的图会被裁切或补黑边，画面会失真 ——
      这不是环境出错，是你的图集本身不齐。

    ★ 想按组管理图集（pic/1/、pic/2/ … 各一组）也完全可以：
      把图放进子目录，再去配置面板「测试图集 › 图集目录」把这一项填成
      那个【具体目录】，例如 "pic/1"。
      注意 "pic"."dir" 指的是一个具体目录，不是它的父目录；
      dir 留空时默认读工程根的 pic/，也就是图直接放在 pic/1.bmp、pic/2.bmp。
      改这一项就能切换整组图，不需要动任何算法代码。

    ★ 图集也可以放在工程外（多个工程共用一份，或放在另一个盘）。
      这时「图集目录」填绝对路径即可，例如 "D:/共享图集/直道组"。
      构建时它会被原样使用，不会被拼到工程目录下面。

--------------------------------------------------------------------------------
 二、图片格式与尺寸
--------------------------------------------------------------------------------
    现支持格式：BMP 与 PNG。
        BMP：单通道 8 位灰度、或 24 位真彩色都可以；
             真彩色会被自动转成灰度。
        PNG：8 位灰度、真彩色、或调色板都可以（非交织）。
            ★ 不支持带透明通道的 PNG（RGBA / 灰度+Alpha）和 16 位色深 ——
              这类图会被拒收，环境会提示你转格式。用画图另存为 24 位 BMP 最省事。
    同一组图里可以混用不同后缀，由 "pic"."ext" 控制按哪些后缀去找。

        ★ 扩展名不是靠猜的：读哪一类由工程根 scut_project.json 里
             "pic"."ext" 决定（缺省 ".bmp"，可写成 ".png,.bmp" 混着读）。
             你放 .png 却把 ext 留成 ".bmp"，环境会一张都读不到（表现为"黑图"而不是报错）。

    尺寸：必须和 scut_project.json 里 image.width / image.height 一致
        （新工程填 188 x 120）

        这两行改了，图集也必须跟着重新导出一遍。
        尺寸不一致时环境不会报错：源图更大会居中裁剪，更小则只占左上角。
        （核对方法：构建后的输出面板会列出读到的图集与张数。）

    为什么尺寸是编译期常量而不是运行期读出来的：
        因为你的算法里会写 int line[SCUT_IMAGE_H]; 这种数组声明，
        C 语言要求数组长度是编译期常量。所以尺寸必须在编译前就定死。

--------------------------------------------------------------------------------
 三、怎么得到这些图
--------------------------------------------------------------------------------
    推荐顺序：

    1) 实拍最优先。用你自己的摄像头，接上上位机抓图，存成 BMP。
       实拍图才反映真实的光照和镜头畸变，调出来的参数才有意义。

    2) 没有硬件时，可以从录像里抽帧再批量导出成 BMP。

    3) 批量改名 / 转格式可以用 Python（OpenCV 或 Pillow 都行）：
         import cv2, os
         img = cv2.imread("raw.png", cv2.IMREAD_GRAYSCALE)
         img = cv2.resize(img, (188, 120))
         cv2.imwrite("pic/1.bmp", img)      # 放子目录时改成 "pic/1/1.bmp"

--------------------------------------------------------------------------------
 四、跑起来之后，工程根目录会多出这几个文件
--------------------------------------------------------------------------------
    跑仿真时，工程根目录下会自动出现：

        Input_pic.bmp     ← 这一帧【实际喂给算法】的那张图（环境读的就是它）
        OutPic_1.bmp      ← 这一帧的画面（含算法画的标注）
        OutPic_2.bmp      ← 算法自己画的第二张图（没画就没有这个文件）

    它们都是【覆盖写】的：重复跑多少次都只有这几个，不会越存越多。
    Input_pic 的后缀跟着你的图集走（.bmp 图集就是 Input_pic.bmp）。
    保存不计入算法耗时，所以不用担心它影响测速结果。
    （关掉「自动保存输出图」之后只会留下 Input_pic。）

    ★ 为什么要有 Input_pic：
      调参数时经常要问"这一帧到底看的是哪张图"。翻到第 37 张之后，
      工程根里那个 Input_pic 就是答案，不用回 pic/ 里数编号。

      ★ 环境【真的】是从 Input_pic 解码的，不是只放一份副本给你看。
        所以每次翻页 / 跳图，它都会被同步成当前那张。

      ★ 想临时改一张图试试：直接改工程根这个 Input_pic，再点一次
        「下一张」/「上一张」（或重新运行）就能看到效果 ——
        因为环境读的就是它。
        注意它终究是【派生文件】：一旦图集里那张原图变了（换了图、
        或重新保存过），下次加载会用原图把它覆盖掉。
        想长期保留改动，就把改好的图存成 pic/ 里的一张。

      ★★ 升级插件之后看不到这个文件？先重新编译一次 ★★
        它是由【仿真程序】（.scut/bin/scut_sim.exe）写出来的，不是插件写的。
        所以装上新版插件、但没重新编译的话，跑的还是旧程序 ——
        旧程序里根本没有这段代码，工程根自然什么都不会多出来。
        下一步：点一次「编译仿真程序」，再运行。

    ★ 想改格式或关掉保存：
      配置面板「输出图保存」那一组 —— 格式可选 BMP / PNG
      （BMP 双击就能看、文件大；PNG 体积约是它的 1/5），
      不想要这两个文件就把「自动保存输出图」关掉。

--------------------------------------------------------------------------------
 五、没有图会怎样
--------------------------------------------------------------------------------
    不会构建失败 —— pic/ 是运行期数据，不是编译期依赖。
    但没有图的话，仿真画面会全黑，算法无从验证。

    在真正上路之前，请务必用【足够多、足够杂】的实拍图跑一遍：
    直道、弯道、十字、坡道、反光、逆光、阴影、丢线……
    只在几张漂亮的图上调参数，上车一定会翻车。
